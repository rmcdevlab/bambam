# CR-059 — Progress updates (text + photos) while a job is in progress; app-logo favicon

Status: DONE (2026-11-24) — owner accepted 2026-11-24 (`repair-cr-059`); approved 2026-11-23 from the owner's answers
Requested: 2026-11-23 by owner
Size: M
Modules: repair (main), settings (one new permission key in the S24 matrix), app shell (favicon)

## What changes

1. **Favicon = app logo.** The Next.js default favicon is replaced by the BAM wordmark (white, from `public/brand/bam-logo.webp`) on a rounded tile with the logo's blue → violet gradient: `app/favicon.ico` (16 / 32 / 48 / 64 px) + `app/apple-icon.png` (180 px, full bleed for phone home screens).
2. **อัปเดตความคืบหน้า.** While a job is กำลังดำเนินการ (step `in_repair`, or `reworking` after a send back), a technician or Admin can post a progress update: a message (required, 1–500) and 0–5 photos. Each update is a timeline event that everyone who can see the ticket reads (reporter, followers, technicians, Admin), on screen and in the PDF report. Updates cannot be edited or deleted (like every other timeline event).

Owner answers (2026-11-23):

| Question | Answer |
|---|---|
| Who can post | ช่าง + Admin → new permission `repair.ticket.update_progress`, seeded to every role that has `repair.ticket.work` and to `admin` (Superadmin always); Superadmin can change it in S24 |
| Who sees it | everyone who can see the ticket |
| When | กำลังซ่อม (`in_repair`) + แก้ไขตามที่ส่งกลับ (`reworking`) — not รับเรื่อง (before เริ่มดำเนินการ), not after บันทึกผล |
| Content | message required every time (1–500); photos optional, max 5 |

## Why

Long jobs (waiting for parts, waiting for a contractor) look stalled to the reporter: between เริ่มดำเนินการ and บันทึกผลซ่อม the timeline shows nothing. The owner wants the technician side to say what is happening, with photos, so the reporter understands without calling.

## Design (S07)

- **Where to add:** button `อัปเดตความคืบหน้า` (outline, `MessageSquarePlus`) in the S07 next-action band, before `เลื่อนวันเสร็จ` / `บันทึกผลซ่อม` (technician) or before `ปิดงาน` (Admin). A second, dashed `+ อัปเดตความคืบหน้า` button sits at the end of the current stage in the timeline, where the new update will appear. Both open the same dialog. Only when `allowedActions` has `update_progress`.
- **Dialog (sheet on phones):** title `อัปเดตความคืบหน้า`, description `ผู้แจ้งและผู้ติดตามจะเห็นข้อความและรูปนี้ในหน้างาน`; `ความคืบหน้าล่าสุด *` textarea (500, counter, placeholder `เช่น สั่งอะไหล่คอมเพรสเซอร์แล้ว คาดว่าของถึงวันพฤหัส`); `รูปประกอบ` (ไม่บังคับ, up to 5, camera on phones); footer ยกเลิก / `ส่งอัปเดต`. Confirm popup (CR-044): `ส่งอัปเดตความคืบหน้า?` · `ผู้แจ้งและผู้ติดตามจะเห็นทันที แก้ไขหรือลบภายหลังไม่ได้`. Unsaved-input close warning (CR-057 `FormDialog`). Toast `ส่งอัปเดตแล้ว ผู้แจ้งเห็นในหน้างานแล้ว`.
- **Timeline:** each update is a card nested under its stage (`กำลังดำเนินการ`, or `ส่งกลับให้แก้` when posted during a rework), oldest → newest like the rest of the timeline: megaphone tag `อัปเดตความคืบหน้า` · date-time, the message in body text (not muted), photo thumbnails (lightbox), `โดย {name}`. The other nested events keep their compact one-line style, so updates stand out.
- **Latest update in the band:** while the job is open, the band shows the newest update of the current work (after the last send back): `อัปเดตล่าสุด {date-time}` + the message (2 lines) + `· รูป {n}`. Reporter (blue hero band) and everyone else (white band).
- **History dialog / PDF:** `อัปเดตความคืบหน้า` rows with the message; the PDF `ดำเนินการซ่อม` / `ส่งกลับให้แก้` section prints the update photos (`ภาพความคืบหน้า n`).
